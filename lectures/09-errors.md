# 第 9 课：让循环知道自己为什么停下

第 8 课处理的是顺利路径。真实任务会遇到模型连接失败、工具参数错误、文件不存在、用户取消、步骤过多。若只有“完成/异常”两种状态，你无法判断是否应继续，更无法安全地重试。

## 先列出可观察的停止原因

至少区分 `finished`、`step_limit`、`model_error`、`cancelled`。工具错误可以成为本轮的观察，让模型修正路径或解释失败；模型请求失败则没有新决策，不能凭空编造一条工具调用。给运行结果保存停止原因、已发生的步骤和是否有最终回答。

| 场景 | 第一版处理 |
| --- | --- |
| 读取不存在的文件 | 把 `not_found` 作为工具结果返回模型 |
| 工具名或参数无效 | 不执行工具，返回结构化错误 |
| 模型连接失败 | 停止本轮，显示 `model_error` |
| 步数达到上限 | 停止请求和执行，显示 `step_limit` |
| 用户中断 | 停止启动新动作，显示 `cancelled` |

## 动手实验

1. 假模型先读错路径，再根据 `not_found` 改读正确路径。确保错误与成功结果各自属于正确调用。
2. 假模型无限请求相同工具；核对实际模型请求次数不超过上限。
3. 在模型调用前或工具调用前触发取消；确认没有启动后续动作。

**完成标准：** 每条失败路径有可解释的状态，终端不把 `step_limit` 或 `cancelled` 显示成“任务完成”。本课先不自动重试写操作；第 12 课会解释副作用结果不明时为什么不能盲目重放。

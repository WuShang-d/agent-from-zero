# 第 6 课：先写一个普通工具，再谈模型调用它

现在的对话 Agent 能说“我帮你计算”，却无法改变程序之外的任何事。不要马上让模型决定工具。先由**你写的 Python 代码**实现、调用、验证一个工具，理解“模型建议动作”和“程序真的执行”之间的边界。

## 第一个工具：计算器

自己写 `calculate(operation, a, b)`，只接受 `add/subtract/multiply/divide` 四种操作与数字参数。除数为零、未知操作、字符串参数都要产生可辨认的错误。不要用 `eval()` 执行模型给出的表达式。先从终端菜单手动选择操作，证明工具本身正确；此时模型还没参与选择。

再写一个**只读**的 `read_file(path)`，只允许读取[课程练习项目](lab/sample_project/README.md)的副本。它可以用来观察 `stats.py`，但不能修改。路径、越界与符号链接边界先做基本校验；第 11 课再讨论操作系统级隔离。

## 为什么需要结果对象

成功返回“结果是 3”不够。让工具统一返回“成功或失败、内容、错误类型”，这样下一课才能把观察交给模型。今天的调用者仍是你写的固定菜单，而不是自然语言解析器。

## 动手与验收

1. 对计算器亲手写至少四个例子：`1+2`、`8/2`、除零、未知操作；检查成功值和错误类型。
2. 读取练习项目的 `stats.py`，再尝试不存在的文件和目录外的文件；观察清楚的失败结果。
3. 在纸上画出“终端菜单 → 工具函数 → 工具结果”。圈出哪一步真正接触文件系统。

**完成标准：** 不启动模型也能验证两个工具；模型回复“我已经读了文件”不会触发任何工具。下课将由模型输出**结构化调用意图**，程序再决定是否执行。

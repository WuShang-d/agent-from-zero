# 第 2 课：让模型调用成为可替换接口

**上一版的失败。** `DemoDecider` 总会在第二步结束；换任务也不会给出真正的回答。若直接把某家 SDK 塞进 `Agent.run()`，循环、网络错误与消息格式会绑死在一起。

## 本课要建的边界

定义与服务商无关的 `Message(role, content)`、`ModelRequest(messages)`、`ModelResponse(text, usage?)` 和 `ModelAdapter.complete(request)`。`usage` 允许缺失，因为不是每种后端都返回相同计数。第一版可只支持文本回答；工具调用在第 5 课扩展。把服务商原始响应转换成自己的数据结构，并把超时或认证失败作为明确错误返回或抛出。

一条最小契约可以长这样：输入 `ModelRequest(messages=(Message("user", "2+2=?"),))`，假模型返回 `ModelResponse(text="4", usage=None)`。业务代码只看本地结构；服务商的响应 ID、停止原因、用量字段由适配器转换并保存到诊断信息中。不要把 `usage=None` 填成零：未知与零消耗是两回事。

## 动手实验

1. 建一个 `FakeModel`，按调用顺序返回预设的两条回复，并保存每次收到的完整 `ModelRequest`。只用它跑单轮 CLI，先不要改变现有循环的含义。
2. 再写一个真实 `ModelAdapter`：密钥从环境读取，日志只记请求 ID、耗时、消息角色与可得的用量，不记密钥。具体 API 字段以选定后端的当前文档为准。
3. 故意让假模型抛出超时、返回空文本，再明确 CLI 显示什么；不能把空文本悄悄称为成功。

**验收。** 对同一输入，切换假模型和真实适配器无需修改 CLI 的消息组织逻辑。无凭据时假模型仍可完成测试；日志不包含密钥。真实请求如未运行，要标明“未验证”，不能用假模型通过冒充真实接入完成。

**设计记录。** 画出 `CLI → ModelAdapter → 后端`，标出谁负责重试、谁决定是否把结果送进循环。下一课的多轮对话需要保留消息，而模型本身不会替程序保存会话。

# 第 3 课：对话为什么能“记得”上一轮

**上一版的失败。** 连续问“我叫小吴”和“我叫什么”，如果第二次请求只含第二句话，模型没有足够信息回答。把上一轮重新放进请求的是应用，不是模型参数里长出了私人记忆。

## 两份对象

`history` 是会话里已发生的原始消息；`working_context` 是这一次请求实际带给模型的有序消息。两者暂时可以相同，但不能是同一个可变列表。建议由 `ContextBuilder.build(system, history, current_user)` 返回不可变序列，并让调用轨迹记录角色与内容长度。

## 动手实验

1. 用 `FakeModel` 断言第二次请求的顺序是 system、第一轮 user、第一轮 assistant、第二轮 user。不要只测试消息总数。
2. 让第一轮回答包含一个故意错误的名字；检查第二轮实际看到的是用户给的名字还是仅仅一条摘要。这个实验用于发现“历史由谁写入”的歧义，不检验模型是否一定答对。
3. 清空 `history` 后重复第二轮；确认请求中再无第一轮的信息。把每轮 `working_context` 保存成可检查的文本或 JSON，敏感内容要脱敏。

**验收。** 能分别打印原始历史和本轮请求，证明“未提交给模型的信息不会因会话文件存在而自动可见”。本课不做长历史裁剪；下一课用超长历史制造窗口问题。

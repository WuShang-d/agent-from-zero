# 第 16 课：让子 Agent 做一件受限的事

一个编码任务常要先查资料、再改代码、最后复核。把所有过程堆在同一份上下文里可能变得又长又乱。这里先做一个**只读探索子任务**，观察独立上下文与权限边界是否带来收益；不因为文章有子 Agent，就立即做复杂并行调度。

## 子任务契约

父任务传入明确目标、允许读取的路径和最大步数；子任务有独立消息、事件与**只读工具集**。它返回 `status、findings、evidence_refs、cost`，其中发现必须指向实际读取记录。父任务接收摘要即可，不把子任务的全部历史塞回自己的工作上下文。

## 动手实验

1. 父任务问“练习项目的失败测试可能在哪里出错”，让 `explore` 子任务读取两个文件并指出证据。
2. 让子任务请求写入。即使父任务有写权限，子任务也必须被自己的工具集与策略拒绝。
3. 注入子任务超时，观察父任务能否继续、重试或向用户说明，而不是丢失自己的状态。

**完成标准：** 轨迹能看出父子 ID、独立预算、只读边界和证据来源。用固定任务比较单 Agent 与子 Agent 的调用次数、延迟和正确性；无收益就如实记录。第一版串行执行即可。

# 第 3 课：让对话 Agent 拥有当前会话的记忆

第 2 课的外层循环只让程序活着，每次请求仍是“失忆”的。现在增加一个最简单的**状态**：进程内的 `messages` 列表。它不是训练模型，也不是长期记忆文件，只是当前会话准备在下一次请求里重放的消息。

## 自己管理消息顺序

一次成功的对话应按顺序留下 `user → assistant`。下一轮先把新 `user` 追加到列表，再把完整列表发给模型，成功后追加它的 `assistant` 回答。若请求失败，这一轮的用户消息和半成品回答如何处理？本课选择一个一致规则并写在注释里，例如：失败时撤回这条待发送的用户消息，保持历史成对；不要一边显示“失败”，一边把它当成成功对话。

```text
第 1 次请求：[user: 我叫小吴]
成功后状态：[user: 我叫小吴, assistant: 你好，小吴]
第 2 次请求：[user: 我叫小吴, assistant: 你好，小吴, user: 我叫什么]
```

模型是否准确回答由模型能力决定；**程序正确性看第 2 次请求里是否确实有第一轮消息**。可以临时打印每轮的角色顺序来检查，完成后关掉详细日志。

## 动手实验

1. 在 `main.py` 增加 `messages` 列表，按上面的顺序追加用户和模型消息。
2. 加 `/reset`：清空当前会话历史，但不退出程序。比较重置前后“我叫什么”的请求内容。
3. 故意关掉 Ollama 服务或让一次调用失败，检查历史中没有“只有 user、没有 assistant”的假成功轮次。恢复服务后继续对话。

## 完成标准

第二轮请求包含此前的用户与助手消息；`/reset` 后只包含新输入；失败轮次的状态符合你选定的规则。你能用实际请求解释“模型本身没有私人会话记忆，是程序把历史交回给它”。

# 从一次模型调用到可恢复的 Agent Harness

这是一门**边做边验证**的课程，而不是对文章的逐段摘要。每课先制造上一版的具体失败，再增加一个负责该失败的部件，最后用轨迹和测试确认行为。图是系统概念图，不是本仓库已经实现的架构图。课程按能力依赖排序，不声称是严格的技术发展年表。

## 从哪里开始

当前仓库已有一个纯演示的 `Agent` 循环：`python3 -m agent_from_zero "查看项目结构"`。它没有模型、工具或真实任务执行能力。第 1 课先审计它；第 2 课接入模型接口；到第 6 课才把模型、工具与观察连成实际 Agent 循环。前一个仓库的手搓模型不作为这里的推理后端。所有课都应保留无需 API 的假模型测试；真实模型由学习者选择支持所需功能的服务或本地模型。

建议贯穿使用 [lab/sample_project](lab/sample_project/README.md)：它包含一个确定的 bug 和失败测试。先在只读模式下找问题；第 11 课完成执行边界后，才允许 Agent 修改练习项目。每课在代码之外保存一份最小轨迹和一页简短设计记录：失败如何出现、哪个部件负责、增加了什么成本。

## 完成一课的标准

1. 先跑出讲义中的失败场景，写下输入和观察到的错误行为。
2. 按本课建议修改代码，不照搬概念图中的框架名称。
3. 跑通**成功案例与边界案例**，保存实际命令、输出和代码版本。
4. 在设计记录里解释：模型决定了什么，运行时决定了什么；下一课要解决哪一个剩余问题。

讲义中的接口名、伪代码和测试名称是教学目标；只有 README“当前里程碑”与仓库测试能说明目前代码的真实状态。外部项目的实现细节会更新，源码阅读时记录所看的版本。

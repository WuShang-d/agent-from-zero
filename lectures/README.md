# 从对话程序到 Agent Harness：亲手逐层写出来

这门课的起点是**空的 Agent 实现目录**。讲义不会先替你写好 `Agent.run()` 再让你阅读。每一课都接着上一课的程序：先看到一个具体限制，再亲手增加最少的代码解决它。第 1 课只做单轮对话；第 2 课形成最简单的对话 Agent；第 8 课才写任务内部的工具运行循环。

## 先分清两种循环

```text
对话循环：用户说一句 → 调用模型 → 显示回答 → 等用户下一句
任务循环：模型要求工具 → 程序执行 → 把结果给模型 → 模型继续，直到最终回答
```

第一种使程序能连续聊天；第二种使它能根据环境反馈连续行动。课程先完成第一种，再引出第二种。“Agent”有宽窄不同的定义；这里把早期对话助手称为**入门版 Agent**，到第 8 课才具备工具驱动的行动闭环。课程只按学习依赖排列，不声称各部件严格按此历史顺序出现。

## 学习方式

- 在仓库根目录由你创建 `main.py`，以后按课程需要拆出模块；讲义只提供接口形状、局部示例和验收任务，不提交预写好的 Agent 成品。
- 默认使用本地 Ollama 的 Chat API；挑选一个**已经下载**的对话模型即可。每课都保留假模型或固定响应作为验证手段，避免把模型输出的随机性当作程序正确性。
- 每课留下三样东西：这一课写出的代码、一条成功轨迹、一条边界或失败轨迹。代码实现后再运行测试；讲义里的测试名称是你要编写的目标，不是当前仓库已通过的测试。
- [贯穿练习项目](lab/sample_project/README.md)只在后期用来练习读代码和修 bug；它故意有失败测试，**不是 Agent 实现**。前期不要修改它。

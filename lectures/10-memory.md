# 第 10 课：跨会话记忆需要写入和读取规则

**上一版的失败。** 新 session 不应重放全部旧任务，但用户稳定偏好或项目约定可能仍有用。把每条工具错误都存成“经验”会污染后续任务。

## 最小记忆记录

用 JSON 或 Markdown 保存 `id、内容、类型、来源 session/event、写入时间、版本、状态`。`semantic` 可放稳定事实或偏好，`episodic` 指向一次任务经历，`procedural` 指向经验证的流程。候选事实先经过写入门槛：是否有来源、是否经用户明确确认、是否与旧值冲突、是否包含秘密。检索先用关键词，不急着引入向量库。注入工作上下文时标出“检索到的记录”和来源，不能把它提升为系统指令。

例子：用户明确说“以后给我的测试命令用 `python3`”，可形成带原始事件 ID 的偏好候选；模型推断“用户大概喜欢 `pytest`”则不能自动写成事实。后来用户改口时，不覆盖旧记录的来源，而是把旧版本标记为过期、创建新版本。这样才能解释为什么当前上下文使用某个偏好。

## 动手实验

1. 在会话 A 中记录用户明确的格式偏好；新建会话 B，检索并引用该偏好。检查 B 没有加载 A 的完整日志。
2. 在会话 C 中让用户纠正偏好；保留旧记录的变更历史，但新检索只返回生效版本。
3. 注入一条“工具读取失败，因为文件暂时不存在”，确认它不会自动变成稳定项目事实。再放入无来源的伪记忆，确认默认不注入。

**验收。** 可以逐条回答：这条记忆从哪里来、为什么写入、何时失效、这次为什么被检索。比较有无记忆时的同一道跨会话问题，记录实际差异，不能只看模型自述。

**阅读。** [RAG](https://arxiv.org/abs/2005.11401) 与 [MemGPT](https://arxiv.org/abs/2310.08560)提供外部知识与分层存储的思路；课程中的偏好更新和注入规则需要自己测试。
